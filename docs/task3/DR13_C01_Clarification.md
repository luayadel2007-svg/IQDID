# توضيح DR13-C01: ما المقصود بـ«العرض»؟

المصدر الأصلي: API_Contracts_v1.0 ، الفصل 6 في الوثيقة المجمعة v1.1 ، سطر 1996 ضمن STD-02. عبارته: «وأسماء حقول أنواع الإثبات وخوارزميات التوقيع والعرض [غ]». لا يسمي حقلاً خاصاً بـ«طرق العرض»، ولا يعرّف مقصود المؤلف بشكل قاطع. العبارة اللاحقة «طرق العرض» كانت صياغة تلخيصية؛ ليست اسم حقل معياري.

التفسير الهندسي القابل للتحقق يفصل المعاني التالية:

| المعنى | الحقول/المصدر | حد الاستنتاج |
|---|---|---|
| إثبات حيازة المفتاح أثناء الإصدار | proof_types_supported و jwt.proof_signing_alg_values_supported ؛ OpenID4VCI1.0 §12.2.4/F.1 | لا يعادل عرض اعتماد للمتَحقق |
| توقيع الاعتماد الصادر | credential_signing_alg_values_supported ؛ §12.2.4 | مستقل عن خوارزمية توقيع proof |
| ربط الاعتماد بالمفتاح | cryptographic_binding_methods_supported ؛ §8.1/12.2.4 | طرق تمثيل المفتاح، لا طرق عرض UI أو نقل VP |
| عرضه بصرياً للمستخدم | credential_metadata.display ؛ §12.2.4 | معلومات UI اختيارية؛ مصفوفة غير فارغة عند وجودها و name داخل عنصرها مطلوب |
| تقديم الاعتماد للمتحقق | OpenID4VP1.0 §5/6 و vp_formats_supported/response_mode وفق موضعها | بروتوكول آخر؛ لا يُضاف presentation_methods_supported إلى metadata المصدِّر بالاستنتاج |

المراجع: https://openid.net/specs/openid-4-verifiable-credential-issuance-1_0.html#section-12.2.4 و https://openid.net/specs/openid-4-verifiable-presentations-1_0.html . هذه أسماء معيارية وتصنيفها، لا سياسة جديدة ولا ادعاء معرفة قصد مؤلف الأصل. C01 صار محدداً كحزمة أسئلة واضحة؛ الغموض التاريخي محفوظ ومعلن. اختبار T01 يغطي هذه الحقول والارتباطات المعنية، ولا يدعي اختبار كل metadata أو كل display/VP profile.

النتيجة: توضيح النطاق PASS ؛ فاحص العقد المحدود PASS ؛ فحص المكتبة FAIL في ثلاث حالات رفض. هذه النتيجة لا تُغلق التوافق الكامل أو بوابة G1a. لا تعديل OpenAPI أو حقول مطلوبة في هذه الدورة.
